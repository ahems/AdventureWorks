# Data API builder entity reference: 69 entities, roles, policies and relationships

This page lists every entity that Data API builder (DAB) exposes from the AdventureWorks Azure SQL database, and which application role may do what with it.

**How this page was derived.** The tables were generated by a script from [`api/dab-config.json`](../../api/dab-config.json) (the `entities` section: `source`, `permissions` and `relationships`). The GraphQL list and single-record names were then checked against the deployed DAB GraphQL schema by introspection: all 138 query field names match. If you change `dab-config.json`, regenerate or update this page.

## Totals

| Item | Count |
|---|---|
| Entities | 69 (66 tables, 3 views, 0 stored procedures) |
| GraphQL query fields | 138 (one list and one `_by_pk` query per entity) |
| Relationships | 76, defined on 40 entities |
| Entities readable without signing in (`anonymous`) | 33 (read only) |
| Entities with REST or GraphQL name overrides | 0 (all names are DAB defaults) |

Every entity uses DAB's default names:

- **REST:** `/api/<Entity>` for lists and `/api/<Entity>/<key>/<value>` for one item. Entity names are case-sensitive, for example `/api/Product`.
- **GraphQL:** a camel-case plural list query (for example `people`, `productCategories`) and a `<camelSingular>_by_pk` query, plus `create<Entity>`, `update<Entity>` and `delete<Entity>` mutations where a role allows them.
- **MCP:** the same entities are available to agents through DAB's `/mcp` endpoint.

See [DAB naming conventions](../architecture/dab-naming-conventions.md) for the naming rules and [Data API builder service](../services/dab-api.md) for authentication, pagination and examples.

## Roles

A caller picks a role with the `X-MS-API-ROLE` header. The role must be in the `roles` claim of the api-mcp-issued token. With a token but no header the caller gets `authenticated`; with no token the caller is `anonymous`.

| Role | Who uses it | Entities with any access | Entities with write access |
|---|---|---|---|
| `anonymous` | Storefront visitors who are not signed in | 33 | 0 |
| `authenticated` | Any signed-in caller with no role header (same permissions as `consumer`) | 42 | 7 |
| `consumer` | Signed-in shoppers | 42 | 7 |
| `sales-admin` | Admin portal sales staff | 61 | 56 |
| `marketing-admin` | Admin portal marketing staff | 61 | 56 |
| `inventory-admin` | Admin portal inventory staff | 65 | 62 |
| `operations-admin` | Admin portal operations staff | 65 | 62 |
| `executive-admin` | Admin portal executives (all entities except `ShoppingCartItem`) | 68 | 62 |
| `manufacturing-engineer` | Manufacturing portal users | 46 | 8 |

Consumer and authenticated writes are limited to their own rows on `BusinessEntity`, `Customer`, `EmailAddress`, `Person`, `PersonCreditCard`, `PersonPhone` and `ProductReview`. Manufacturing engineers can write `BillOfMaterials`, `Location`, `Product`, `ProductInventory`, `ProductModel`, `ScrapReason`, `WorkOrder` and `WorkOrderRouting`.

## Row-level policies

DAB database policies filter rows by claims in the token, so shoppers only see and change their own data.

| Policy | Entities |
|---|---|
| `@item.BusinessEntityID eq @claims.business_entity_id` | `BusinessEntity`, `BusinessEntityAddress`, `Person`, `EmailAddress`, `PersonPhone`, `PersonCreditCard` |
| `@item.PersonID eq @claims.business_entity_id` | `Customer` |
| `@item.CustomerID eq @claims.customer_id` | `SalesOrderHeader` |
| `@item.ShoppingCartID eq @claims.business_entity_id` | `ShoppingCartItem` |
| `@item.UserID eq @claims.business_entity_id` | `ProductReview` (create) |

Shoppers can update only the `HelpfulVotes` field of a `ProductReview`, with no ownership policy, so any signed-in shopper can vote a review helpful.

## Tables not exposed through DAB

| Table | Why | Where the data is served instead |
|---|---|---|
| `Person.Address` | The `SpatialLocation` column uses the SQL `geography` type, which DAB does not support | `AddressFunctions` in Azure Functions |
| `HumanResources.Employee` | `hierarchyid` columns | The `Employee` entity, backed by the view `HumanResources.vEmployee` |
| `Production.Document`, `Production.ProductDocument` | `Document.DocumentNode` is a `hierarchyid` column | Not exposed |
| `Sales.GuestCartSession` | Guest-cart state is owned by Functions | Cart routes in Azure Functions |
| `dbo.RealtimeNotificationOutbox` | Internal real-time outbox written by SQL triggers | `DatabaseChanges` SQL trigger function |
| `dbo.AWBuildVersion`, `dbo.ErrorLog` | Not used by the application | Not exposed |
