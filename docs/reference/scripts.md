# Scripts reference: azd hooks, utilities, generators and data-management tools

This page lists every script in the [`scripts/`](../../scripts/) directory, what it does and when to run it. Test scripts live in [`tests/scripts/`](../../tests/scripts/README.md) and are not listed here.

**How this page was derived.** The list was generated by enumerating `scripts/**` (excluding `__pycache__`). Each purpose comes from the script's header comment or docstring. The **How it runs** column comes from `azure.yaml` hook definitions, the `.github/workflows/` files and references from other hooks, tests and docs.

## Rules for running scripts against the demo environment

The deployed environment is a disposable demo. Fix source code, Bicep, seed scripts or hooks and redeploy; do not repair Azure resources by hand. When you use these scripts:

- **azd hooks** run automatically during `azd up`, `azd provision` and `azd deploy`. Do not run them by hand to patch an environment.
- **Authenticated API calls** must get tokens from [`scripts/utilities/azure-auth.py`](../../scripts/utilities/azure-auth.py). See [authenticated local scripts](../testing/AZURE_AUTHENTICATED_SCRIPTS.md).
- **Direct SQL scripts** need public SQL access, which deployment disables. Do not reopen SQL networking to run them; use the deployed DAB or Functions APIs instead.
- **One-off data scripts** produced checked-in seed data. Rerun them only when you intend to regenerate that data, then redeploy through the seed job.

Legend for **How it runs**: *Hook* = run by azd from `azure.yaml`; *Workflow* = used by GitHub Actions; *Operator* = run by a person when needed; *One-off* = data generation or maintenance whose output is committed.

## azd lifecycle hooks (`scripts/hooks/`)

| Script | Purpose | How it runs |
|---|---|---|
| [`preup.sh`](../../scripts/hooks/preup.sh) | Persists the signed-in user and subscription, creates the resource group and Foundry account, and selects available chat, embedding and image models and capacity | Hook: `preup` |
| [`postprovision.sh`](../../scripts/hooks/postprovision.sh) | Reconciles runtime RBAC, builds the seed-job image and starts the seed job asynchronously, creates the `mcp-signing` Key Vault certificate, and creates the Foundry agents | Hook: `postprovision` |
| [`predeploy.sh`](../../scripts/hooks/predeploy.sh) | Writes `app/.env.production` and renders the storefront Static Web App configuration | Hook: `predeploy` |
| [`postdeploy.sh`](../../scripts/hooks/postdeploy.sh) | Publishes `MANUFACTURING_AGENT_ENDPOINT`, trusts the hosted agent in api-mcp, sets OAuth redirect URIs and trusted principals on api-mcp, refreshes Foundry agents when their definition changes, and reapplies Functions agent settings | Hook: `postdeploy` |
| [`postup.sh`](../../scripts/hooks/postup.sh) | Deploys the hosted Manufacturing agent if its endpoint is missing, disables public SQL access and removes the temporary client firewall rule, and prints service URLs and seed status | Hook: `postup` |
| [`api-postdeploy.sh`](../../scripts/hooks/api-postdeploy.sh) | Sets the `APP_URL` environment variable on the DAB container app (DAB CORS itself is fixed in `dab-config.json`) | Hook: `api` service `postdeploy` |
| [`api-functions-postdeploy.sh`](../../scripts/hooks/api-functions-postdeploy.sh) | Writes Foundry agent IDs, `MCP_SERVICE_URL` and `MANUFACTURING_AGENT_ENDPOINT` to the Function App settings | Hook: `api-functions` service `postdeploy`; also called by `postdeploy.sh` |
| [`app-postdeploy.sh`](../../scripts/hooks/app-postdeploy.sh) | Sets the `API_MCP_URL` app setting on the storefront Static Web App | Hook: `app` service `postdeploy` |
| [`seed-job-execution.sh`](../../scripts/hooks/seed-job-execution.sh) | Starts a seed-job execution and reports its name | Called by `postprovision.sh` and the deployment workflow |
| [`app-admin-postdeploy.sh`](../../scripts/hooks/app-admin-postdeploy.sh) | Admin postdeploy settings | Not referenced by `azure.yaml` |
